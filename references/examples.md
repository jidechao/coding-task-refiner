# 完整案例：从模糊到精确

## 场景

需求：电费计算接口要加一条新的峰谷电价规则。

---

## 原始描述（模糊版）

> 帮我改一下电费计算，加个峰谷电价。

**诊断**：
- 缺少文件定位（哪个文件？哪个方法？）
- 缺少规范依据（按什么规范实现？）
- 缺少范围边界（只改计算逻辑还是连文档一起改？）
- 缺少验收标准（怎么算改完了？）

---

## 四步法梳理过程

### Phase 1: 说清楚

梳理结果：
- **文件定位**：ElectricityCalcService.java（主逻辑）、ElectricitySettlementService.java（参考范本）
- **规范依据**：电费计算接口规范v1.2
- **范例参照**：新接口实现参考 ElectricitySettlementService.java
- **范围边界**：只处理峰谷电价计算规则，不修改阶梯电价和其他计费规则
- **测试文件**：ElectricityCalcServiceTest.java

### Phase 2: 问明白

加入的指令：
- "分析当前实现为什么无法支持新的峰谷电价规则？依据是什么？"
- "对无法从代码和规范确定的业务规则，先向我提问，不要自行假设。"

### Phase 3: 控过程

加入的指令：
- "分析此次变更会影响哪些设计文档、接口定义、数据模型、代码和测试用例。"
- "给出完整修改计划，不要立即修改代码。"（人工闸门）

### Phase 4: 验结果

加入的指令：
- "执行编译和单元测试。"
- "根据《电费计算接口规范v1.2》，重新核查生成代码的参数、接口调用和异常处理是否符合规范。"
- "核查设计文档和接口定义是否已同步更新。"
- "检查 Git Diff，确认没有动到授权范围之外的文件。"

---

## 优化后的提示词（最终输出）

```
【上下文】
阅读以下文件：
- 电费计算接口规范v1.2
- ElectricityCalcService.java
- ElectricitySettlementService.java
- ElectricityCalcServiceTest.java 及相关测试用例

【范围边界】
本次任务只处理峰谷电价计算规则的新增实现，不修改阶梯电价和其他计费规则。

【范例参照】
新接口实现参考 ElectricitySettlementService.java 的代码结构和命名规范。

【分析要求】
分析当前实现为什么无法支持新的峰谷电价规则，说明依据。
对无法从代码和规范确定的业务规则，先向我提问，不要自行假设。

【影响分析】
分析此次变更会影响哪些设计文档、接口定义、数据模型、代码和测试用例，
列出需要同步修改的关联项。

【执行闸门】
给出完整修改计划（含文件清单和修改内容摘要），不要立即修改代码。
等我确认后再执行修改。

【验收标准】
修改完成后：
1. 运行编译和全部单元测试，确保通过。
2. 根据《电费计算接口规范v1.2》，重新核查代码的参数、接口调用和异常处理。
3. 确认设计文档和接口定义已同步更新。
4. 检查 Git Diff，确认没有动到授权范围之外的文件。
5. 列出验证结果摘要。
```

## 对比

| 维度 | 模糊版 | 优化版 |
|------|--------|--------|
| 文件定位 | 无 | 4 个具体文件 |
| 规范依据 | 无 | 电费计算接口规范v1.2 |

| 验收标准 | 无 | 三层验收 + Diff 检查 |
| AI 猜错概率 | 极高 | 极低 |
