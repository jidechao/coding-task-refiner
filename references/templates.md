# 五类任务提示词模板

## 1. 排查类

适用场景：找问题、查隐患、审代码。

```
排查 [范围/目录] 下所有 [对象类型]，找出 [具体问题]。
给出问题位置、事实依据、影响范围和修改建议。
先分析，不要修改。
```

**填充示例**：
```
排查 /power-metering/src/main/java/settlement/ 下所有 Service 类，
找出未按《电费计算接口规范v1.2》拼装输入字段的调用点。
给出问题位置、事实依据、影响范围和修改建议。
先分析，不要修改。
```

---

## 2. 理解类

适用场景：搞清楚现有代码/设计的来龙去脉。

```
请先阅读 [相关文件/代码]，分析 [具体问题] 的原因。
请根据项目代码、接口文档和相关规范判断依据，
如果没有找到明确依据，直接说没有，不要猜测。
对无法从现有上下文确定的信息，先向我提问。
```

**填充示例**：
```
请先阅读 ElectricityCalcService.java、ElectricitySettlementService.java
和电费计算接口规范v1.2，分析当前峰谷电价计算逻辑的实现方式。
请根据代码和规范判断依据，如果没有找到明确依据，直接说没有。
对无法确定的业务规则，先向我提问。
```

---

## 3. 生成类

适用场景：写新代码、生成文档、创建测试。

```
基于 [源文件/规范]，生成 [目标产物]。
格式参考 [模板文件/范本]。
不确定内容先提出问题，不要自行假设。
```

**填充示例**：
```
基于 electricity-calc-spec-v1.2.md 和 ElectricityCalcService.java，
生成分布式光伏接入的电费计算模块。
格式参考 ElectricitySettlementService.java 的代码结构和命名规范。
不确定内容先提出问题，不要自行假设。
```

---

## 4. 变更类

适用场景：修改现有代码、更新配置、调整接口。

```
根据已经确认的方案，修改 [范围]。
修改前检查关联的设计文档、代码和测试用例。
本次任务只处理 [具体内容]，不修改 [排除范围]。
先给出修改计划，确认后再执行。
不要修改未授权范围的文件。
```

**填充示例**：
```
根据已确认的方案，修改 ElectricityCalcService.java 中的峰谷电价计算逻辑。
修改前检查关联的设计文档、接口定义、数据模型和测试用例。
本次任务只处理峰谷电价规则，不修改阶梯电价和其他计费规则。
先给出完整修改计划，确认后再执行。
不要修改未授权范围的文件。
```

---

## 5. 收口类

适用场景：验证、核查、收尾确认。

```
核查本次变更涉及的全部设计文档、代码、接口和测试。
检查是否存在遗漏、不一致或违反规范的地方。
根据 [具体规范名称]，重新核查生成代码的参数、接口调用和异常处理。
通过代码检索、测试运行和 Git Diff 进行验证，并列出验证结果。
确认没有动到授权范围之外的文件。
```

**填充示例**：
```
核查本次峰谷电价变更涉及的全部设计文档、代码、接口和测试。
检查是否存在遗漏、不一致或违反规范的地方。
根据《电费计算接口规范v1.2》，重新核查生成代码的参数、接口调用和异常处理。
通过编译、单元测试和 Git Diff 进行验证，并列出验证结果。
确认没有动到授权范围之外的文件。
```

---

## 组合使用

复杂任务通常需要组合多个模板。典型组合：

| 组合 | 适用场景 |
|------|---------|
| 理解 + 变更 + 收口 | 先搞清楚再改再验 |
| 排查 + 变更 | 查出问题后修复 |
| 生成 + 收口 | 写新代码后验证 |
| 理解 + 生成 + 变更 + 收口 | 完整的需求实现闭环 |
